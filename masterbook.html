1Basics
1Concepts

Core definitions

  • AI: Machines doing tasks that normally need human thinking.
  • Machine learning: AI that learns patterns from data.
  • Deep learning: Machine learning with large multi-layer neural networks.
  • Data, model, training, inference: Examples, learned pattern, learning process, and using the model on new input.

Types of AI

  • Narrow, general, super AI: One-task AI, human-level AI, and AI beyond humans. Only narrow AI exists today.
  • Prediction, generation, decision-making: Predict a result, create something new, or choose an action.

Key ideas

  • Generalization: Working on examples the model never saw.
  • Parameters vs hyperparameters: The model learns parameters. You choose hyperparameters.
  • GIGO (Garbage In, Garbage Out): Bad data in, bad results out, however smart the model is.
2Methods and Tools
  • Problem framing: Define who needs help, what output they need, and how success is measured.
  • Baselines: Start with a simple rule or average, so you have something to beat.
  • Prototype vs production: A prototype tests an idea. Production must run reliably for users.

Define the product

  • Product definition: Name the user, the decision they must make, their current workaround, and their constraints.
  • Verifiable outcome: Turn a wish like "find the best tool" into a result you can test.
  • Required vs preferred: A missing required feature fails a candidate. A preference only changes the ranking.
  • Acceptance example: Accept a tool when a source supports the feature. "Free to install" does not prove the feature is free. Excellent ratings do not fix a missing feature.
  • Delegation: AI can write most of the code. You still own the requirements, permissions, tests, and release decision.
3Practice and Judgment
  • Common mistake: Starting with a complex model before a baseline.
  • Check: Can you explain the problem, the data, and the success measure in one paragraph?
  • Uncertainty and abstention: A good system admits when it is unsure.
  • Practice: Write ten real user questions. Answer three by hand with evidence. Include one that should end in "insufficient evidence." Keep them as your first evaluation set.
  • Progress rule: Move on only when you can show the result, explain a failure, and undo the change.
2Math
1Concepts

Linear algebra

  • Vectors and matrices: Data and weights are stored as numbers in lists and tables.
  • Dot product and cosine similarity: Measure how strongly two vectors match.
  • Eigenvectors and SVD: Find the main patterns in a matrix.
  • Matrix operations: Transpose, inverse, rank, and determinant describe how a matrix transforms data.

Probability and statistics

  • Probability and Bayes' rule: Measure likelihood and update beliefs with evidence.
  • Distributions and sampling: Describe outcomes and draw examples from them.
  • Key distributions: Normal (bell curve), Bernoulli and binomial (yes/no counts), Poisson (event counts), uniform (all equal).
  • Expectation, variance, covariance: Average, spread, and how values move together.
  • Confidence intervals and hypothesis tests: Check whether a result is real or chance.

Information and calculus

  • Entropy, cross-entropy, KL divergence: Measure uncertainty and how different two distributions are.
  • Derivatives, chain rule, gradients: Show how a small input change affects the output.
  • Integrals: Add up many small pieces, used for areas under curves and for probabilities.
2Methods and Tools
  • Maximum likelihood and MAP: Choose settings that best explain the data.
  • Bootstrap: Resample data to see how much a result varies.
  • Optimization: Find the best solution within limits.
  • Numerical stability: Keep calculations reliable with very large or small numbers.
  • Tools: NumPy and SciPy for math, Jupyter for experiments.
3Practice and Judgment
  • Practice: Implement a dot product, a gradient, and a softmax by hand in Python.
  • Common mistake: Trusting a result without checking its uncertainty.
  • Check: Can you explain what a gradient tells the model?
3Programming and File Formats
1Concepts

Core skills

  • Python: The main language for AI.
  • Shell and command line: Run programs, move files, and automate tasks.
  • Data structures and runtime cost: Choose efficient storage and estimate speed.

Python basics

  • Values: Strings, numbers, booleans, lists, and dictionaries.
  • Control: Conditions, loops, and functions.
  • Structure: Modules, exceptions, and reading files.

How the web works

  • Files and processes: Folders, paths, terminal commands, programs, and processes.
  • URLs, browsers, servers: The browser asks, the server answers.
  • HTTP: Requests, responses, and status codes (200 OK, 404 not found, 500 server error).
  • Journey of one request: Button, backend, and back. A disconnected browser, a failed server, and an empty search each show up at a different step.

File formats for AI

  • Markdown (.md): Plain text with simple markup. Best for prompts, notes, and project instructions.
  • JSON and JSON Lines (.jsonl): Structured data for APIs. JSON Lines stores one record per line.
  • YAML: Readable settings and configuration files.
  • CSV, Parquet, Arrow: Tables in text or column-based formats.
  • NumPy files (.npy, .npz): Saved arrays.
  • Unicode and UTF-8: Reliable text storage across languages.
2Methods and Tools
  • Git and GitHub: Track changes and collaborate through branches and reviews.
  • SQL: Filter, join, and summarize stored records.
  • Environments: Separate packages for each project and record their versions.
  • Environment variables and secrets: Keep API keys out of code.
  • Testing and debugging: Check expected behavior and trace failures.
  • Debugging steps: Reproduce the failure, capture the input, inspect values, read logs and tracebacks, and find the first wrong step.
  • Test levels: Unit test (one function), integration test (connected parts), end-to-end test (a full user journey).

Project handoff

  • Git in practice: Commits, branches, diffs, and rollback to a working version.
  • README: Setup instructions that a stranger can follow.
  • Project brief: Decisions made, changes AI may make, and acceptance tests.
  • Fresh-session test: A new AI session reads the files, runs the tests, and explains the next feature.
3Practice and Judgment
  • Practice: Write a script that reads a CSV, cleans it, and saves a JSON file.
  • Common mistake: Putting API keys inside code that gets shared.
  • Check: Does your project run on a fresh environment from your instructions?
  • Practice: Ask AI to explain a ten-line function with one sample input. Predict which records a filter keeps, change one rule, run it, and compare.
  • Practice: Catch a ranking mistake with a failing test. Confirm it passes after the fix and an unrelated search still works.
4Data
1Concepts

Data basics

  • Features and labels: Inputs the model uses, and the answers it predicts.
  • Representative sampling: Data should match real-world use.
  • Annotation quality: Clear labeling rules and agreement between labelers.

Records and evidence

  • Record design: Define field types, IDs, dates, and missing values.
  • Provenance and freshness: Store where a fact came from and when it was checked.
  • Evidence record: Feature support, installation price, feature price, evidence URL, and date checked.
  • Unknown is a valid value: Leave unsupported fields unknown. Never guess.
  • Access and usage terms: Check permission and conditions before building a feature around an outside source.

Data risks

  • Data leakage: Information that would be unavailable at prediction time sneaks into training.
  • Class imbalance: Rare outcomes need special handling.
  • GIGO: Poor data quality limits every model built on it. Fix data before changing models.
2Methods and Tools
  • Splits: Train, validation, and test sets. Use stratified, grouped, or time-based splits when needed.
  • Quality checks: Find missing values, duplicates, and invalid ranges.
  • Preparation: Encode categories, scale numbers, and create features.
  • Augmentation and synthetic data: Create controlled variations or simulated examples, then check their quality.
  • Pipelines and versioning: Track data lineage, versions, and documentation.
  • Tools: pandas, DuckDB for local queries, Spark for large jobs, DVC for data versions.

Storing and querying

  • Start with SQLite: Move to PostgreSQL when many users and background jobs share a database.
  • Tables and keys: Primary keys identify a row. Foreign keys link tables.
  • Indexes and transactions: Faster lookups, and changes that succeed or fail together.
  • Schema migrations: Change the structure without losing old records.
  • Safe refresh: Refreshing a record twice must not create duplicates.
3Practice and Judgment
  • Practice: Audit a messy dataset and list every problem before modeling.
  • Common mistake: Tuning on the test set.
  • Check: Can someone else reproduce your dataset from its documentation?
  • Practice: Retrieve one permitted sample record and store it with its evidence URL and date. Refresh it twice and confirm there are no duplicates.
5Classic Machine Learning
1Concepts

Learning types

  • Supervised: Learn from labeled data.
  • Unsupervised: Find patterns without labels.
  • Reinforcement: Learn from rewards and trial and error.
  • Semi-supervised and self-supervised: Use few labels or let data create its own labels.

Core tasks

  • Regression: Predict a number.
  • Classification: Predict a category.
  • Clustering: Group similar items.
  • Anomaly detection: Flag unusual records.
2Methods and Tools

Models

  • Linear and logistic regression: Simple, explainable baselines.
  • Trees and ensembles: Decision trees, random forests, and boosting (XGBoost, LightGBM).
  • Other models: Nearest neighbors, Naive Bayes, and SVMs.

Training practice

  • Regularization: Keep models simple.
  • Cross-validation and tuning: Compare settings fairly using random or Bayesian search.
  • Calibration and dimensionality reduction: Check probability accuracy and summarize inputs with PCA or UMAP.

Other areas

  • Bandits and reinforcement basics: Balance trying new options with using known good ones.
  • Reinforcement learning in depth: Reward design, exploration vs exploitation, MDPs, Q-learning, policy gradients, and multi-agent RL.
  • Causal inference: Estimate what happens when you change something.

Tools: scikit-learn, XGBoost, LightGBM.

3Practice and Judgment
  • Practice: Compare a simple rule, a linear model, and boosted trees on the same data.
  • Common mistake: Using a complex model without a simple baseline.
  • Check: Does the model underfit or overfit? Read the bias-variance balance.
6Neural Network Training
1Concepts

Building blocks

  • Neuron, weight, bias, layer: The smallest pieces of a neural network.
  • Activation function: Adds non-linearity so the network learns complex patterns.
  • Loss function: Measures how wrong predictions are.

Learning process

  • Gradient descent and backpropagation: Update weights step by step to reduce loss.
  • Tensors and shapes: Data stored as arrays, with sizes that must match across operations.
2Methods and Tools
  • Optimizers: AdamW and momentum SGD control how weights are updated.
  • Learning rate and schedules: Set step size, often starting with warmup.
  • Epochs and mini-batches: Passes over data, and small groups processed together.
  • Stability tools: Weight initialization, normalization layers, and gradient checks.
  • Regularization in training: Dropout, weight decay, and early stopping.
  • Automatic differentiation: Libraries calculate gradients for you.
  • Tools: PyTorch or TensorFlow.
3Practice and Judgment
  • Practice: Build a small network in PyTorch that learns a simple pattern.
  • Common mistake: A learning rate that is too high, causing the loss to jump around.
  • Check: Read the learning curves. Are training and validation loss both falling?
7Deep Learning Architectures
1Concepts

Architectures

  • CNN: Good at images, finds edges and shapes with small filters.
  • RNN, LSTM, GRU: Process sequences one step at a time.
  • Transformer: Reads all parts of the input at once with attention. Basis of modern AI.
  • Autoencoders and VAEs: Compress data and rebuild it.
  • Graph neural networks: Learn from linked data, like social networks or molecules.
  • State-space models: Efficient sequence models that keep a compact state.

Key ideas

  • Positional encoding: Tells a Transformer word order.
  • Residual connections: Skip paths that make deep networks trainable.
  • Mixture of Experts: Only some parts of a large model run for each input.
2Methods and Tools
  • Self-supervised and contrastive learning: Create learning targets from the data itself.
  • Knowledge distillation: A small model learns to copy a large one.
  • Transfer learning: Reuse a model trained on one task for another.
  • Continual learning: Learn new tasks without forgetting old ones.
3Practice and Judgment
  • Practice: Fine-tune a pretrained CNN on your own image set.
  • Common mistake: Training from scratch when a pretrained model would work.
  • Check: Can you explain which architecture fits which kind of data?
8Large Language Models
1Concepts

How LLMs read

  • Tokens: Small text pieces that models read and write.
  • Embeddings: Number lists that capture meaning.
  • Attention: Lets each word look at other words for context.
  • Context window: How much text the model can consider at once.

How LLMs learn

  • Pretraining: Predict the next token on huge amounts of text.
  • Model types: Decoder-only (GPT style), encoder-only (BERT style), encoder-decoder.
  • Scaling laws: Bigger models, more data, and more compute predictably help. The Chinchilla rule suggests about 20 training tokens per parameter.
2Methods and Tools

Generating answers

  • Temperature, top-p, top-k, beam search: Control how the model picks words.
  • Chat templates and roles: Format system, user, and assistant messages correctly.
  • KV cache: Speeds up long answers.

Adapting models

  • Prompting: Zero-shot, few-shot, in-context learning, chain-of-thought.
  • Instruction tuning: Teach the model to follow instructions.
  • LoRA and QLoRA: Cheap fine-tuning with small add-on layers.
  • Preference training: RLHF, DPO, and reward models. PPO is a common reinforcement learning method for this, and GRPO compares several answers to the same question.
  • Verifiable rewards: Score answers with tests or exact answers.

Limits

  • Hallucination: Confident wrong answers.
  • Knowledge cutoff: The date after which the model has no training data.
  • Long-context limits: Details buried in long inputs can be missed.
  • Multilingual gaps: Quality varies across languages.
  • Sycophancy: The model agrees with you even when you are wrong.
  • Three different jobs: Generation writes, lookup finds, and calculation computes. A model can write a convincing price claim from incomplete evidence, so check it against a source.

Selecting a model

  • Same tasks, fair comparison: Run the same examples through hosted and local models.
  • Measure: Task quality, response time, input and output cost, language coverage, context needs, and privacy.
  • Benchmarks: Use public ones only to build a shortlist. Confirm on your own examples.
  • Record and justify: Save settings, costs, and failure cases, then explain the choice.
3Practice and Judgment
  • Practice: Compare the same task with zero-shot and few-shot prompts and record the difference.
  • Common mistake: Trusting an LLM answer without checking the source.
  • Check: Does the answer match your evaluation set?
  • Practice: Run the same examples through two models and write down the settings, costs, and failures.
9Generative AI
1Concepts

Generation types

  • Text, image, audio, video, 3D: Different outputs from different models.
  • Diffusion models: Turn noise into a clear image step by step.
  • Autoregressive generation: Create output one piece at a time.
  • Flow matching and normalizing flows: Other methods that move from noise to output.
  • GANs: Older method where a generator and a judge compete.
2Methods and Tools
  • Latent diffusion: Work in compressed space for speed.
  • Conditioning and guidance: Steer output with prompts, poses, layouts, or style references.
  • Editing: Inpainting and outpainting.
  • Consistency: Keep identity and style steady across edits and frames.
  • Neural codecs: Compact audio and video representations.
  • Tools: Diffusers for code, ComfyUI for visual workflows.
3Practice and Judgment
  • Practice: Generate the same image with three different prompts and compare.
  • Common mistake: Ignoring rights to training data and outputs.
  • Check: Is the output consistent across edits? Does it show clear AI origin where needed?

Language and vision

  • NLP: Understanding and writing language.
  • Computer vision: Understanding images and video.
  • Speech AI: Speech to text and text to speech.

Other areas

  • Recommendation and search: Rank items by relevance.

  • Robotics and simulation: Control machines, often tested in simulations first.
  • Science and healthcare: Discovery and medical support.

  • Document AI and OCR: Read forms, tables, and scans.
  • Graph analytics: Find fraud or hidden links in networks.
  • Operations research: Optimize schedules, routes, and inventory.
  • Geospatial AI: Analyze satellite images and maps.
  • Edge and industrial AI: Run models on devices, sometimes offline.
  • Multi-agent systems and human-AI interaction: Several AIs working together, and designing how people guide them.
  • Domain AI: Law (contract review), finance (risk, fraud, forecasting), music, games, and robotics control each need domain experts and special validation.
  • Research and knowledge systems: Search ranking, information extraction, knowledge graphs, conflicting sources, citation checking, and curated test sets.
  • Voice, image, and video products: Streaming, latency, and media-specific evaluation.
  • Predictive business software: Forecasting, experiments, data pipelines, and drift monitoring.
  • Industry applications: Real domain workflows, realistic records, expert validation, system integration, and the cost of a wrong decision.
  • When to specialize: Add a topic only when you can name the product requirement or failure that needs it.
3Practice and Judgment
  • Practice: Build one application end to end, such as a receipt reader.
  • Common mistake: Choosing a fancy model when a simple rule works.
  • Check: Do real users succeed with it?
11Building AI Applications
1Concepts

Core ideas

  • Context engineering: Decide exactly what the model sees for each task.
  • Structured output: Force answers into a fixed format like JSON.
  • Grounding: Tie answers to real sources and check citations.

Architecture

  • RAG: Retrieve documents first, then answer from them.
  • Vector databases: Store embeddings for fast similarity search.
  • Agents: Models that plan, use tools, and check progress.
  • Multi-agent systems: Several agents specialized for different roles.

One request, end to end

  • Flow: The interface collects the question. The backend validates it. Search finds candidates. Code removes duplicates and enforces requirements. The model reads passages and explains. A database saves the evidence and date. Logs record what happened.
  • Debug order: If the right tool never entered the candidate list, inspect retrieval before changing the final prompt.
  • Partial vs complete: Show clearly when a source failed, and do not confuse that with zero matches.
2Methods and Tools

Building retrieval

  • Chunking, hybrid search, reranking: Split documents well, combine keyword and semantic search, then reorder results.
  • Parsing, metadata, source quality: Clean documents, keep source and date, and prefer reliable sources.
  • Citations: Show the passage and link behind every recommendation.
  • Three separate failures: A missing source, a poor passage, and a misread passage. Diagnose each on its own.

Agent building

  • Tool calling and MCP: Connect models to tools and data through a standard.
  • Memory: Short-term for the current task, long-term across sessions.
  • Memory types: Facts (what is true), events (what happened), and procedures (how to do things). Keep them separate.
  • Computer-use agents: AI that controls a screen with a mouse and keyboard.
  • Agentic coding: AI that plans, writes, tests, and fixes code on its own.
  • Workflows and harnesses: Fixed steps or AI-chosen steps, with rules for permissions and stopping.
  • Model routing and caching: Pick models by task and reuse answers to save cost.

Project files for AI

  • Markdown instructions: CLAUDE.md and AGENTS.md tell coding agents how a project works.
  • llms.txt: A Markdown file that gives AI a clean map of a website.
  • Skills files: Reusable instruction folders for specific tasks.

Other tools

  • A2A: A protocol for agents to hand off tasks.
  • Frameworks: LangChain, LlamaIndex, LangGraph.

Learning and self-improving agents

  • Skill library: The AI saves each working solution as a reusable skill and picks from the library next time.
  • Failure memory: After a failed attempt, the system writes a short lesson and checks it before the next try.
  • Council and debate: Several models answer and critique each other, then a judge picks or merges the result.
  • Preference learning: Learn your taste from what you approve or reject, so suggestions get more personal.

Choosing a method

  • Prompting first, RAG for knowledge, fine-tuning for behavior.

Prompt and context design

  • Prompt parts: Objective, definitions, examples, counterexamples, allowed sources, output format, and rules for uncertainty.
  • Per-call context: Decide exactly what goes into each call.
  • Validate in code: Check the returned fields in your application, not by trust.
  • Request to filters: Convert a natural request into required features and preferences. Handle ambiguity and malformed output. Keep unknown prices visible.

Workflow controls

  • Tool schemas and validated arguments: Check every tool call before it runs.
  • Fixed vs agent-chosen steps: Use a fixed workflow unless open choice is needed.
  • Budgets: Set limits on time, tool calls, and spending.
  • Failed lookup: Stop within budget, return the evidence already found, and say what is unresolved.

Memory and customization

  • Four separate things: Conversation context, saved preferences, retrieved material, and learned model parameters.
  • Fix a specific failure with the cheapest tool: Compare a prompt change, a lookup, a deterministic algorithm, and fine-tuning.
  • Changing facts like prices: Refresh from sources instead of training them in.
  • Fine-tuning: Needs many examples of the exact failure and the correct output.

External APIs

  • Read the docs first: Methods, headers, payloads, and authentication.
  • Server-side credentials: Never put keys in the browser.
  • Pagination, rate limits, timeouts: Fetch all pages, slow down when limited, and use a bounded number of retries.
  • Error handling: An unavailable source is not the same as a successful search with zero matches.

Candidate pipeline

  • Merge by identity: Use sets and dictionaries to remove duplicates.
  • Keyword search and ranking: Start with a baseline you can reproduce without a model.
  • Required-feature filter: A popular but irrelevant tool must not pass.
  • Explain and audit: Explain each top result and look for a relevant tool you missed (precision and recall).

Interface

  • Basics: Forms, input validation, accessibility, loading and error states.
  • Show evidence: Let users open the supporting passage and tell partial results from complete ones.
  • Let users correct assumptions: Make the system's guesses visible and editable.
  • Start simple: A basic Python interface comes before a separate frontend stack.
3Practice and Judgment
  • Practice: Build a RAG app that answers questions from your own PDFs with citations.
  • Common mistake: Fine-tuning when better retrieval would solve the problem.
  • Check: Does each answer point to a source passage that supports it?
  • Practice: Fetch two pages of results and combine them. Then simulate an unavailable source and compare the response with a search that has zero matches.
  • Practice: Simulate a failed lookup. The system should stop within budget and say what is unresolved.
  • Check: Can a new user enter a question, open the supporting passage, and tell partial from complete results?
12Deployment and Production
1Concepts
  • Deployment: Making a model available to users, usually through an API.
  • Latency and throughput: How fast one request is served, and how many the system handles.
  • Reliability: Timeouts, fallbacks, and service targets.

System design

  • Boundaries and data flow: Draw the whole system on one page.
  • Sync vs background work: Slow jobs run in the background through queues.
  • Concurrency and stale data: Plan for simultaneous searches, old cache entries, and slow sources.
  • Idempotency: Retrying an action must not repeat its effect, such as a double payment.
  • Code, model, or human: Decide which steps use each.
2Methods and Tools

Serving

  • Endpoints, batch jobs, streaming: Three ways to deliver results.
  • Serving engines: vLLM for efficient language model serving.
  • Containers and scaling: Docker to package, Kubernetes to scale.

Speed and size

  • Quantization and pruning: Smaller numbers and fewer parts for lighter models.
  • Distillation: Train a small model from a large one.
  • Batching and caching: Process requests together and reuse results.
  • Mixed precision: Smaller number formats for faster training.

Model formats

  • Safetensors: Safe format for model weights.
  • GGUF: Format for running models locally.
  • ONNX: Format for moving models between tools.

Release and monitoring

  • CI/CD: Automatic tests before release.
  • Shadow tests, canaries, rollback: Test quietly, release gradually, undo if needed.
  • Drift and training-serving skew: Detect changing data or mismatched preparation.
  • Tracing and observability: Follow each request to find slow or broken steps.
  • Cloud and GPUs: Rent compute from AWS, Google Cloud, or Azure.

Training at scale

  • Distributed training and sharding: Split work across many GPUs (FSDP, ZeRO).
  • Checkpoints: Save progress so training can resume.

Operating the product

  • Environments and config: Local vs hosted, pinned dependency versions, and settings kept out of code.
  • Publish simple first: Add infrastructure only when needed.
  • Alerts, backups, restore: Test that a backup can actually be restored.
  • Load testing: Check behavior under many users before launch.
  • Cost per successful task: Count failed attempts, retries, response time, human review, support, provider dependency, and source licenses.
  • Release evidence: Decide in advance what results justify releasing or reverting a version.
  • Feedback: Use user feedback to choose the next change.
3Practice and Judgment
  • Practice: Deploy one model as an API, then add monitoring.
  • Common mistake: Deploying without a rollback plan.
  • Check: Can you roll back to the previous version in minutes?
  • Practice: Walk through simultaneous searches, a stale cache, a slow source, and a restarted job. Show that a retry cannot duplicate an action.
  • Practice: Share a working link, trace one failed request, restore a test backup, and roll back a bad release. A second person should reproduce your deployment from the notes.
  • Practice: Estimate the cost of 1,000 successful searches from measured usage, including failures.
13Responsible AI, Safety, and Governance
1Concepts

Fairness and privacy

  • Bias and fairness: Check whether some groups get worse results.
  • Privacy: Differential privacy and federated learning protect personal data.
  • Consent and data rights: Permission to collect and use data.

Safety

  • Alignment: Making AI do what humans intend.
  • Hallucination and misuse: Confident errors, scams, and deepfakes.
  • Reward hacking: Shortcuts that score well but miss the real goal.
  • Scalable oversight: Using AI to help humans check AI that is too complex to check alone.
  • AI control: Designing systems so AI cannot cause harm even if it misbehaves.
  • Deceptive alignment: A model that behaves well only while it is being tested.
2Methods and Tools

Security

  • Threat modeling and red teaming: Find what could go wrong and test it.
  • Prompt injection defense: Treat text in documents and web pages as untrusted.
  • Data poisoning and supply chain: Verify where data, packages, and models come from.
  • Least privilege and sandboxing: Give AI only the access it needs.
  • Approval gates: Humans approve high-impact actions.
  • Adversarial examples: Tiny input changes that fool a model, like a sticker that makes a sign misread.
  • Model stealing: Copying a model by querying it many times.
  • Membership inference: Testing whether a specific record was in the training data.

Documentation and rules

  • Model cards and impact assessments: Record purpose, limits, and test results.
  • Watermarking and provenance: Mark or trace AI-made content.
  • Copyright and licensing: Check rights for data, code, models, and outputs.
  • NIST AI RMF and the EU AI Act: Risk frameworks and laws.
  • India's DPDP Act (2023): India's data protection law, covering consent and handling of personal data. Check the current rules and deadlines before relying on them.
  • Dangerous capability evals: Tests for whether a model could help with weapons or cyberattacks.
  • Compute governance: Rules that track or limit large amounts of computing power.
  • Responsible scaling policies: A company's rules for adding safeguards or pausing as models get stronger.
  • Incident response: Define who can stop a system and how harm is handled.

Accounts, data, and sources

  • Authentication vs authorization: Who you are, versus what you may access.
  • User isolation: Each user sees only their own records.
  • Input validation and secrets: Check all inputs, and keep keys in a secret manager.
  • Retention and deletion: Decide how long data is kept and how it is removed.
  • Source permission: Confirm you may use each outside source.
  • Clean logs: Logs must not contain credentials.

Wider impact

  • Jobs, energy, water, and access: Social and environmental effects.
3Practice and Judgment
  • Practice: Write a model card for one of your projects.
  • Common mistake: Shipping without knowing who the system could harm.
  • Check: Can you name who can stop your system right now?
  • Practice: Test with two dummy users, each seeing only their own records. Confirm that instructions hidden in a retrieved page cannot grant access or trigger an unauthorized action.
14Research Frontier
1Concepts

Scaling and reasoning

  • Scaling laws and compute limits: Predictable gains, but finite resources.
  • Test-time compute: Think longer during an answer for harder problems.
  • Reasoning models: Models that work through steps before answering.
  • Emergent abilities: Skills that seem to appear suddenly as models grow. Some may be measurement effects, and this is debated.
  • Grokking: A model suddenly generalizes long after it has memorized the training data.

Self-improvement

  • Recursive self-improvement (RSI): An AI improves parts of its own improvement process, so each round can make the next better. Current demos are limited to narrow tasks.
  • Safe RSI loop: Run, test on a fixed set, find failures, propose one change, retest, get human approval, archive the old version.
  • RSI safety rules: Humans approve changes. The judge and test set stay out of the system's reach. Change one thing at a time. Protect core rules. Always keep a rollback.
  • Intelligence explosion: A theory that unchecked RSI could speed up very fast. It is a debated risk, not a proven outcome.
  • Self-training with synthetic data: Learn from AI-produced examples that are checked.
  • Model collapse: Quality can fall when models learn only from AI output.
2Methods and Tools
  • Process supervision: Feedback on each reasoning step.
  • Self-refinement: The model critiques and revises its own answer.
  • AI-assisted research loops: Propose, test, and improve ideas automatically (AlphaEvolve).
  • Test-time adaptation and machine unlearning: Adjust during use, or remove a training example's influence.

Understanding models

  • Mechanistic interpretability: Study which internal parts cause a behavior.
  • Neuro-symbolic AI: Combine learning with logic and rules.

Other frontiers

  • World models and embodied AI: Models of how environments change, and AI in physical bodies.
  • Long-horizon agency: Agents that handle many steps and recover from errors.
  • Multimodal AI: Models that handle text, images, audio, and video.
  • Open vs closed models: Downloadable models vs hosted services.
3Practice and Judgment
  • Practice: Read one recent paper and reproduce a single result.
  • Common mistake: Believing a demo shows general ability.
  • Check: Have you separated what is proven from what is claimed?
15Projects
1Concepts
  • Projects prove skill. Each project should test one idea end to end.
  • Completion standard: You are done with the core when you can build a new application from a blank project, explain a wrong result, improve it using evidence, and recover from a bad release.
2Methods and Tools
  • Tabular comparison: Rule vs linear model vs boosted trees.
  • Data audit: Find leakage and duplicates, then measure the effect of fixing them.
  • Forecast with backtesting: Predict and replay past periods.
  • Document extraction: Scanned invoices to validated fields.
  • Recommendation prototype: Compare against a popularity baseline.
  • Chatbot and RAG app: LLM API plus your own documents.
  • Agent with tools: An AI that uses search or calculators.
  • Evaluation suite: Tests, version comparison, and release blockers.
  • Paper reproduction: Match a published result closely.
  • Deployed app: Put one project online for others to use.

Build ladder (RR Engineer)

  • 1. Searchable catalog: Python and SQLite with 50 hand-picked records. Pass: you can change a ranking rule and explain the effect.
  • 2. First wrapper: One model call that turns a request into validated filters. Pass: required features survive rewording, and ambiguity is handled openly.
  • 3. Evidence-backed researcher: One live source with passages, links, and timestamps. Pass: every claim is traceable and unsupported claims stay unknown.
  • 4. Multi-source researcher: A second source, deduplication, ranking, caching, and time limits. Pass: losing a source gives clearly labeled partial results within budget.
  • 5. Released product: Hosted interface, evaluation suite, feedback, monitoring, and rollback. Pass: someone uses it unaided and you can diagnose their failed request.
  • 6. Transfer project: A different application, such as a supplier-quotation comparison tool. Trace every quoted price to its source and keep missing freight terms unknown. Explain what design you reused and what you changed.

Brief for an AI coding assistant

  • Fill in for each feature: User and decision, one feature to build, inputs and permitted sources, expected output with evidence, one example that should pass, one that should fail, handling of missing or contradictory evidence, maximum time, cost, and tool calls, and actions needing your approval.
  • Before editing, the AI explains: The smallest workable design, files affected, and the assumption most likely to be wrong.
  • After editing, the AI shows: The diff, test results, reproduction and rollback steps, and anything it could not verify.
  • Keep some test questions private until evaluation.
3Practice and Judgment
  • Rule: Write a short README for each project with the problem, method, result, and limits.
  • Check: Can someone else run it from your instructions?
  • Review loop: Define success yourself. Ask AI for options and choose one. Inspect the change, run a normal case and a failure case, then a held-out example. Release only when you can explain the result and recover the previous version.
16Classical AI, Search, and Planning
1Concepts
  • Search: Finding a path from a start state to a goal.
  • Logic and knowledge: Facts, rules, and knowledge graphs.
  • Planning: Choosing steps that reach a goal, even under uncertainty.
2Methods and Tools
  • Search methods: Breadth-first, depth-first, A*.
  • Heuristics: Quick estimates that guide search.
  • Game search: Minimax and Monte Carlo tree search.
  • Constraint solving: SAT and SMT solvers for rule-based problems.
  • Probabilistic models: Graphical models for uncertain variables.
  • Fuzzy logic and evolutionary algorithms: Partial truth and evolving candidates.
  • Historical systems: Expert systems were rule-based AI from the 1980s.
3Practice and Judgment
  • Practice: Solve a maze with A* and compare it with breadth-first search.
  • Common mistake: Ignoring classical methods when they are simpler and cheaper.
17Evaluation and Measurement
1Concepts
  • Evaluation: Measuring whether a system is good for its real purpose.
  • Metrics: Accuracy, precision, recall, and cost of errors.
  • Benchmarks: Standard tests such as MMLU and SWE-bench.
2Methods and Tools

Test design

  • Gold sets and rubrics: Trusted examples and scoring rules. Every module needs one, and no change ships unless it passes.
  • Component and end-to-end tests: Locate where failures start.
  • Slice testing and error analysis: Find weak groups and failure types.
  • Ranking and text metrics: Precision@k, recall@k, and NDCG score ranked results. BLEU and ROUGE compare text to a reference but are weak for open-ended answers.

Quality checks

  • Uncertainty in scores: Check whether differences are real.
  • Robustness and distribution shift: Test noisy or changed inputs.
  • Benchmark contamination: Check for test data leaking into training.

Judges and humans

  • Human evaluation: Shared rubrics and agreement between raters.
  • LLM-as-judge: One model scores another, checked against humans.

Agents and online

  • Agent evaluation: Task completion, tool use, and recovery.
  • Online experiments: A/B tests with real users.
  • Task time horizons (METR): How long tasks an AI can finish reliably.

Evaluating a whole system

  • Held-out set: Keep it out of your build instructions.
  • Hard cases to include: Near matches, contradictory sources, stale facts, unknowns, and service failures.
  • Track: Retrieval quality, citation support, task success, latency, and cost.
  • Version comparison: Run the new version and the baseline on identical cases. Report improvements and regressions separately.
  • Better-sounding is not better: Inspect an answer that reads well but scores worse.

Tools: Inspect AI, lm-evaluation-harness.

3Practice and Judgment
  • Practice: Build a 50-example test set for one of your projects.
  • Common mistake: Choosing a benchmark that does not match your use case.
  • Practice: Explain how testing on examples used during development inflates accuracy, and sketch a separate held-out set.
  • Start early: Begin testing from your first project and deepen it later.
18Hardware and Large-Scale Computing

2Methods and Tools

22Resource Discovery and Filtering
1Concepts

The discovery problem

  • Too much to review: GitHub, Hugging Face, the Chrome Web Store, YouTube, and Instagram hold far more than anyone can scan.
  • Goal: Describe a need in plain English, filter across sources, and get a short list with evidence for each pick. Another long directory does not solve this.
  • Reality: No single tool does all of it today. The closest setup is a custom search lens, plus platform filters, plus a check at the source.

Three jobs

  • Discovery: Find new things you do not know yet.
  • Organization: Group what you already follow.
  • Blocking: Hide what you do not want. One tool rarely does all three.

Key ideas

  • Popularity is one signal: Stars, ratings, and views are not proof of fit.
  • Verify at the source: Ratings, update dates, features, and prices.
  • Open gap: Finding credible creators you do not follow, especially on Instagram, is still unsolved. Instagram Favorites and Following only organize accounts you already know.
  • Where RR Engineer fits: Run several lenses together, then score each result against your filters and show the evidence.
2Methods and Tools

Custom search lens

  • Brave Search Goggles (free): Rules that boost, downrank, or discard sites on top of Brave Search. Example: $boost=3,site=github.com. Host the rules on GitHub, Gist, or GitLab and submit them at search.brave.com/goggles/create.
  • Kagi Lenses (paid): Up to 10 included sites, 10 excluded sites, 5 included keywords, 5 excluded keywords, plus file type, region, and date range. It does not support image or video search.
  • Kagi price (confirm before paying): Starter is listed at $5 a month for 300 searches. Kagi's blog says unlimited search is in the $10 Professional plan. Which plans include custom lenses was not confirmed. Check kagi.com/pricing.
  • Limit of both: They find pages only. They do not give ratings, recency, or quality. Check each result at the source.

YouTube: discover, organize, block

  • Discover (SimilarTube, SimilarChannels): Give a channel you trust and get similar ones. SimilarTube needs a sign-in, its listing showed a 2024 version, and one reviewer saw empty results. Test it on 2 or 3 channels first.
  • Organize (PocketTube): Groups channels into collections, shows the latest videos per group, filters by duration, and can remove Shorts on the subscriptions page. Syncs through Google Drive. Free, supported through Patreon.
  • Block (BlockTube): Blocks by video name, channel, keyword, and runtime, and can block Shorts. The Chrome listing shows 100,000 users, updated Feb 2026. Never paste advanced code you do not understand.
  • Alternative: FilterTube (Firefox) has a Whitelist Mode that shows only approved channels. Its user base is small.
  • YouTube's own filter: Duration over 20 minutes removes Shorts.
  • Setup: (1) Subscribe to 2 or 3 trusted channels, run each through SimilarTube, and subscribe to the best 5. (2) Make PocketTube groups: LLM apps, RAG and agents, MLOps, Fundamentals. (3) In BlockTube, block "you won't believe", "insane", "secret", "10x", "killer", "replaces", turn on the Shorts block, and set a minimum runtime of 10 minutes.

Reusable filters

  • GitHub: topic:rag language:python stars:>500 pushed:>2026-05-01 archived:false. Then check recent commits, closed issues, license, and a README with a working example.
  • Hugging Face: Filter by Task, Language, and License (Apache-2.0 or MIT if you plan to sell). Sort by Trending, then Downloads. Read the model card for results on a benchmark that matches your task.
  • Chrome extensions: At least 100 ratings, updated within 12 months, permissions that match the function, and read the 3 newest reviews, not the average.
  • Chrome-Stats Advanced Search: Shortlists extensions by function, ratings, review count, users, and last update. Its page did not load during checking, so confirm the filters and price yourself. Inspect the original Chrome Web Store listing.

Reference shelf

  • Repositories: GitHub Search, GitHub Trending, Awesome lists, Awesome Stars, OSS Insight.
  • Code, models, data: Kaggle Notebooks and Datasets, Hugging Face Models, Datasets, and Spaces, AI4Bharat for Indian languages.
  • Run and compare models: Replicate, OpenRouter, Ollama, Artificial Analysis. Confirm results on your own examples.
  • Find and organize evidence: arXiv, OpenReview, Google Scholar Button, Zotero Connector, DeepL for translation.
  • Packages and workflows: PyPI, PyPI Stats, n8n. Check dependencies and test any imported example.
  • Track and publish: Weights & Biases, Streamlit Community Cloud. Study AWS, Azure, or Google Cloud as deployment needs grow.
  • Social feeds: Instagram Favorites and Following, PocketTube, BlockTube.
3Practice and Judgment
  • Practice: Run the YouTube setup above for AI engineering tutorials: discover channels, group them, and block hype.
  • Practice: Write one GitHub query and one Hugging Face filter for a real need. List your top 3 results with evidence.
  • Common mistake: Trusting popularity. High stars or ratings with no recent updates is usually a dead end.
  • Check: For each pick, can you show a source, the date you checked, and one limitation?
  • Before paying for any tool: Verify its current features and price.
